# عقد API: المهام

هذا العقد هو الاتفاق الوحيد بين واجهة React وLaravel API في المرحلة الأولى. ينبغي ألا يغير أي فريق أسماء الحقول أو بنيتها أو المسارات دون تحديث هذا الملف وطلب دمج منفصل.

## عنوان الخدمة

أثناء التطوير المحلي، يفترض أن تعمل Laravel على العنوان التالي:

```text
http://localhost:8000/api
```

يمكن لفريق React وضع هذا العنوان في متغير بيئة لاحقًا:

```text
VITE_API_URL=http://localhost:8000/api
```

## كيان Task

| الحقل | النوع | مطلوب | الوصف |
|---|---|---:|---|
| `id` | number | ينشئه الخادم | المعرّف الفريد للمهمة |
| `title` | string | نعم | عنوان المهمة، من 3 إلى 255 حرفًا |
| `completed` | boolean | لا | هل أنجزت المهمة؛ القيمة الافتراضية `false` |
| `created_at` | string | ينشئه الخادم | تاريخ الإنشاء بصيغة ISO أو تنسيق Laravel الافتراضي |
| `updated_at` | string | ينشئه الخادم | آخر تاريخ تعديل |

مثال على مهمة يعيدها Laravel:

```json
{
  "id": 1,
  "title": "إنهاء واجب React",
  "completed": false,
  "created_at": "2026-08-20T10:00:00.000000Z",
  "updated_at": "2026-08-20T10:00:00.000000Z"
}
```

## المسارات

| العملية | HTTP | المسار | جسم الطلب | الاستجابة الناجحة |
|---|---|---|---|---|
| جلب الكل | `GET` | `/tasks` | لا يوجد | `200` مع مصفوفة مهام |
| جلب واحدة | `GET` | `/tasks/{id}` | لا يوجد | `200` مع كائن مهمة |
| إضافة | `POST` | `/tasks` | `title`, واختياريًا `completed` | `201` مع المهمة الجديدة |
| تعديل | `PUT` | `/tasks/{id}` | `title` و/أو `completed` | `200` مع المهمة المعدلة |
| حذف | `DELETE` | `/tasks/{id}` | لا يوجد | `204` بلا جسم استجابة |

المسارات أعلاه تكتب بعد `/api`. لذلك يكون طلب القراءة الكامل هكذا:

```text
GET http://localhost:8000/api/tasks
```

## أمثلة الطلبات والاستجابات

### إنشاء مهمة

```http
POST /api/tasks
Content-Type: application/json
```

```json
{
  "title": "إعداد Laravel API",
  "completed": false
}
```

الاستجابة المتوقعة:

```json
{
  "id": 2,
  "title": "إعداد Laravel API",
  "completed": false,
  "created_at": "2026-08-20T10:10:00.000000Z",
  "updated_at": "2026-08-20T10:10:00.000000Z"
}
```

### تعديل حالة الإنجاز

```http
PUT /api/tasks/2
Content-Type: application/json
```

```json
{
  "completed": true
}
```

## معالجة الأخطاء

| الحالة | رمز HTTP | الصيغة المقترحة |
|---|---:|---|
| بيانات غير صحيحة | `422` | كائن Laravel القياسي يحتوي `message` و`errors` |
| المهمة غير موجودة | `404` | كائن يحتوي رسالة مناسبة |
| خطأ غير متوقع | `500` | لا تعرض التفاصيل الداخلية للعميل |

مثال مختصر لخطأ تحقق من العنوان:

```json
{
  "message": "The title field is required.",
  "errors": {
    "title": [
      "The title field is required."
    ]
  }
}
```

## واجهة مؤقتة لفريق React

إلى أن يصبح الباك إند جاهزًا، يمكن لفريق React استخدام هذه البيانات الوهمية نفسها. عند الدمج، يستبدل مصدرها بـ `GET /api/tasks` دون تغيير أسماء الحقول:

```js
const mockTasks = [
  { id: 1, title: "إنهاء واجب React", completed: false },
  { id: 2, title: "إعداد Laravel API", completed: true }
];
```

> معيار الدمج: يجب أن ينجح عرض القائمة، وإضافة مهمة، وتحديث حالتها، وحذفها باستخدام هذا العقد دون أي تحويل إضافي لأسماء الحقول داخل React.
